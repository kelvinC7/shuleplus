ShulePlus School Fees Payment APIs

This guide describes how partner systems integrate with ShulePlus to support parent school fees payments, from student identification through fee quotation, payment initiation, confirmation, and digital receipt verification.

Students API: https://students-api.shuleplus.rw/api School Fees API: https://fees.shuleplus.rw/api Babyeyi BFF: https://babyeyi-api.shuleplus.rw/api

Tip: Use your browser’s Print → Save as PDF to share this guide with your integration team.

Architecture

Banks integrate by calling the same REST APIs used by ShulePlus public pay-fees (babyeyi.rw): Student Management and School Fees Portal microservices — not the IAM developer gateway.

┌─────────────────────┐ │ Bank / Fintech │ Mobile app, internet banking, API hub └──────────┬──────────┘ │ HTTPS (public routes: no Bearer token) ├──────────────────────────────┐ ▼ ▼ students-api.shuleplus.rw/api fees.shuleplus.rw/api GET /public/students/lookup GET /public/student-fees POST /public/payments/initiate GET /public/payments/{ref}/status GET /public/receipts/{receiptNo} │ │ └───────────┬──────────────────┘ ▼ School organization data (PostgreSQL)

Step 3: Initiate payment

POST https://fees.shuleplus.rw/api/public/payments/initiate Public · no auth

Creates a PENDING payment. In production, your bank executes the debit/transfer and confirms via callback (roadmap). Sandbox may auto-complete after polling when configured.

Idempotency: Send header Idempotency-Key with a unique value per customer transaction. Retrying with the same key and same JSON body returns the original 201 response (same reference). Reusing the key with a different body returns 409 — treat as an integration error and investigate.
Important: Use JSON field method values MOMO, BANK, or CARD. Do not use channel.

Common body fields

FieldRequiredDescription
organizationIdYesSchool UUID
studentCodeYes*ShuleCode
studentNameRecommendedDisplay on receipt
academicYear, termYesMust match fee query
amountYesPositive number (RWF)
methodYesMOMO | BANK | CARD

Errors & HTTP status codes

HTTPMeaningTypical cause
401UnauthorizedOn protected school APIs invalid or missing Bearer token
403ForbiddenLicense / tenant not provisioned for the school module
404Not foundUnknown student, payment reference, or receipt
400Bad requestValidation (amount, phone, missing academicYear/term)

Bank integration notes

Current platform capabilities

✅Direct module APIs + Babyeyi BFF (production URLs)
✅Student lookup, fee quotation, payment record (PENDING → COMPLETED)
✅Digital receipts with verification URL / QR
🔜Bank webhook for payment confirmation
🔜Real-time account debit / MoMo STK push via partner CBS
🔜Reconciliation & settlement reporting APIs

Recommended integration pattern

  1. Parent selects school fees payment in your channel.
  2. Your backend calls ShulePlus Steps 1–2 to validate student and amount.
  3. Initiate ShulePlus payment (Step 3) to obtain reference.
  4. Execute debit/transfer in your core banking system.
  5. On success, confirm payment with ShulePlus (callback API coordinate with ShulePlus integration team).
  6. Poll Step 4 or receive webhook when status is COMPLETED; show receipt to parent.

Sandbox testing

  • Use Postman collection 1. End-to-End Pay Fees Flow (direct module URLs).
  • Set students_api_url, fees_api_url, and organization_id in the environment.
  • Optional: collection 0 for IAM health checks and OAuth (not required for public pay).
