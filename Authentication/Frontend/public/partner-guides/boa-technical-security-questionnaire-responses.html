2

Is documentation versioned? Deprecation of older versions?

Yes, at integration-pack level. Current API guide is v1.1 (March 2026). Postman pack is tied to Git commits on the main branch.

We do not yet have a signed contractual SLA document only for API deprecation. Our operational commitment: we notify registered partners before breaking changes to production endpoints and allow a reasonable migration window (we propose 90 days in the partnership agreement).

3

Authentication method (OAuth2, mTLS, API keys)?

APIAuthentication today
Public school fees APIs (bank pay flow)HTTPS only — no Bearer token, same as public parent portal

Not in production today: mTLS on public fees APIs; bank core debit/settlement APIs (BOA CBS side) — to be defined with BOA during design.

Transparency: Public fees endpoints are intentionally open like the website flow. For production, we can discuss IP allowlisting, WAF rules, or API keys if BOA requires additional controls beyond TLS.
4

How credentials are issued, rotated, and revoked

OAuth (Developer Portal): ShulePlus creates partner + sandbox school → bank user activates account (MFA) → creates application → receives client_id and one-time client_secret. Rotation via Rotate Secret (old secret invalid immediately). Revocation via suspend/delete application or developer user.

Secrets stored hashed; plaintext never kept after display. Server/database credentials: small ops team, environment files, not in Git.

5

Dedicated sandbox/UAT separate from production?

Logical separation: yes. Separate OAuth apps (SANDBOX vs PRODUCTION), dedicated sandbox organization_id, test students, Developer Portal MFA.

Transparency: Sandbox currently uses the same public hostnames as production (e.g. fees.shuleplus.rw) with test school data, not a separate physical UAT datacenter. Payment behaviour in sandbox stays PENDING until confirmed (optional auto-confirm only if enabled for demos).
6

Uptime over last 12 months (evidence)

Production runs on a dedicated server with PM2, Nginx, PostgreSQL, and module /health endpoints. Deployments are controlled via GitHub and self-hosted runner.

Honest answer: We do not yet have an audited 12-month uptime percentage or a public status page to attach to this response. We can share operational incident notes and health-check logs on request during UAT. We are working toward a published SLA and monitoring dashboard for partners.
7

Maximum throughput (RPS/RPM)

Architecture is standard HTTP + PostgreSQL; capacity depends on server size and DB connections.

Honest answer: We have not run a formal load test with a certified RPS/RPM number for external partners. We propose joint UAT load testing with BOA before go-live and will share results and scaling plan if limits are reached.
8

Failed requests, timeouts, retries

  • GET (lookup, fees, status, receipt): retry on 5xx/network with backoff (max ~5 attempts).
  • POST initiate: do not blind retry; use bank idempotency mapping (Q9).
  • 4xx: fix payload; do not retry.

Payments stay PENDING until bank confirmation/callback is implemented in production integration.

9

Idempotency

POST …/payments/initiate supports header Idempotency-Key (per organizationId). Same key and same JSON body replays the original 201 (same reference). Same key with a different body returns 409 — investigate; do not auto-retry.

GET calls are idempotent. BOA should still store its own channel idempotency key mapped to ShulePlus reference for reconciliation.

10

Encryption in transit (TLS)

Yes. Partner APIs are served only over HTTPS. TLS terminates at Nginx on *.shuleplus.rw. We configure TLS 1.2+ (TLS 1.3 where supported). Certificates renewed via our standard Let’s Encrypt / server process.

Third-party cloud (AWS/Azure/GCP) and shared responsibility

Core student and fee databases: self-managed server in Rwanda — not AWS/Azure/GCP multi-tenant SaaS for application data.

Third parties used: GitHub (source code; deploy runner on our server), email/SMS providers for notifications. These do not hold the full production database.

Responsibility: ShulePlus — application security, patching, tenant isolation. Host provider — physical/network per contract. BOA — bank channel and CBS security.
